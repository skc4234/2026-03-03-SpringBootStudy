# WebSocket, STOMP, Kafka, Redis 핵심 정리

## 1. 클라이언트 ↔ 서버

### 1) WebSocket (웹소켓)
* **개념**: 클라이언트와 서버 간에 단일 TCP 연결을 통해 **실시간 양방향 통신**을 지원하는 기본 전송 프로토콜입니다.
* **특징**: 최초 연결 시 HTTP Handshake를 거친 후 전용 프로토콜(`ws://`)로 전환되어 낮은 오버헤드로 실시간 데이터를 주고받습니다.

### 2) SockJS
* **개념**: WebSocket을 지원하지 않는 구형 브라우저나 기업용 방화벽/프록시 환경을 위해 동작하는 **Fallback(대체) 라이브러리**입니다.
* **특징**: WebSocket 연결 시도 후 실패 시, HTTP 기반의 대체 통신 기술(HTTP Streaming, HTTP Long Polling 등)로 자동 전환하여 끊김 없는 실시간 경험을 제공합니다.

### 3) STOMP (Simple Text Oriented Messaging Protocol)
* **개념**: WebSocket 위에서 동작하는 **표준 메세징 프레임 프로토콜**입니다.
* **특징**:
  * WebSocket 자체는 단순 바이트/문자열 전송만 지원하므로, 메시지의 구조와 목적지를 정의하는 규격이 필요합니다. STOMP는 이를 위해 표준화된 프레임(Header, Body, Command)을 제공합니다.
  * **예시**:
    * `/topic/...` : 단체 채팅 (예: `/topic/chat`)
    * `/queue/...` 또는 `/user/...` : 1:1 채팅 (예: `/user/chat`)

## 2. 서버 ↔ 서버

### 1) Kafka (분산 이벤트 스트리밍 플랫폼)
* **주요 역할**: **대규모 이벤트 데이터의 수집, 보관 및 비동기 처리**
* **특징**:
  * 메시지를 디스크에 **영속적으로 저장(Persistence)** 하므로, 장애 발생 시 메시지 재처리(Replay) 및 크롤링/로그 데이터의 안정적 보관이 가능합니다.
  * 초당 수십만 건 이상의 대용량 이벤트/메시지 스트림을 처리하는 분산 메시지 큐(Message Queue) 역할을 수행합니다.

### 2) Redis (인메모리 데이터 저장소)
* **주요 역할**: **초고속 데이터 저장, 캐싱 및 실시간 상태 관리**
* **특징**:
  * 모든 데이터를 RAM(메모리)에 저장하여 빠른 읽기/쓰기 성능을 자랑합니다.

## 3. 기술 비교 요약 (Kafka vs. Redis)

| 구분 | Kafka | Redis |
| :--- | :--- | :--- |
| **주 핵심** | **대규모 이벤트 스트리밍** | **인메모리 DB / 임시 저장소** |
| **저장 매체** | 디스크 기반 (메시지 보관 및 영속화 가능) | 메모리(RAM) 기반 (필요 시 디스크 백업 가능) |
| **주요 용도** | 대용량 비동기 메시지 전달 | 빠른 데이터 조회 |

# Spring Security / JWT 비교
| 구분 | Spring Security | JWT |
| :--- | :--- | :--- |
| **로그인** | **ID/PW 확인 -> Session 생성** | **ID/PW 확인 -> JWT 생성** |
| **저장 위치** | 서버(JSESSIONID 쿠키로 세션 식별) | 클라이언트가 JWT 자체를 저장(쿠키 자체로 저장) |
| **이후 요청시** | 세션 확인 → 로그인 사용자 확인 | Authorization: Bearer 전송 → 서버가 JWT 검증 |
| **상태 관리** | 서버가 로그인 상태를 보유 | 상태를 갖지 않음 (토큰만으로 인증) |
